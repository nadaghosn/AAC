# Plan: Add `GET /version`

Status: **Plan only — not implemented.** No files have been modified.

Note: `app/main.py` already has a `GET /json/version` endpoint (`app/main.py:63-69`), which is the direct precedent for this new route.

## 1. File that would need to change

`app/main.py` only. It already imports `FastAPI` and defines route handlers inline (no separate router module exists), and the existing `json_version()` handler (`app/main.py:63-69`) is the direct precedent to follow. No changes needed to `models.py`, `schemas.py`, `storage.py`, or `business_rules.py` — this route needs no request body, no persistence, and no business rule.

## 2. Smallest route to add

```python
@app.get("/version", tags=["root"])
def version() -> dict:
    return {"version": app.version}
```

Placed near `json_version()` (`app/main.py:63-69`), reusing `app.version` (already set to `"0.1.0"` in the `FastAPI(...)` constructor at `app/main.py:32-36`) — same pattern as the existing endpoint, just a narrower response body. No new imports, no new Pydantic model needed (a plain `dict` return is consistent with `root()` and `json_version()`).

## 3. Tests: add or update?

**Add** — not update. `tests/test_tasks.py` currently has no test for `/`, `/json/version`, or `/health` root-level routes (its 44 tests are all task/comment CRUD), so this is a net-new test, e.g. `test_get_version_returns_200_and_version_string`, asserting `response.status_code == 200` and `response.json() == {"version": "0.1.0"}` (or just that the key exists, to avoid hard-coding the version string). No existing test should need modification.

## 4. Command to verify

```bash
pytest -v
```

Per `CLAUDE.md` §3, this discovers the full suite under `tests/`. Optionally, a manual check first:

```bash
uvicorn app.main:app --reload --port 8000
curl http://localhost:8000/version
```

## 5. Risks / scope creep to avoid

- Don't let `/version` duplicate or diverge from `/json/version` — decide whether `/version` replaces it, coexists as an alias, or is intentionally different, before implementing (scope decision, not a code decision).
- Don't return more than a version string (e.g. no build hash, git SHA, environment info) unless explicitly requested — CLAUDE.md's "no major changes without approval" spirit applies.
- Don't add a Pydantic response model for this unless the project's convention shifts — `root()` and `json_version()` intentionally return plain `dict`, not `BaseModel` subclasses like `HealthResponse`.
- Don't touch CORS config, tags structure, or any existing route.
- No dependency, Docker, CI, auth, database, or frontend changes (per constraints) — this stays a single-function, single-file addition.
